# 查询首页编辑式月报重构设计

## 目标

将员工查询首页从常规 KPI 仪表盘重构为“个人月报”式首页，让用户进入系统后首先理解自己的本月整体考勤表现。设计需要具有明显的视觉记忆点，同时保持企业系统长期使用所需的清晰度、稳定性与可读性。

本次只重构查询首页的内容结构和视觉表现，不改变路由、权限模型、接口契约或其他页面样式。

## 设计原则

- 首页回答“我本月整体表现如何”，不以今日状态为主线。
- 使用编辑式、杂志式排版，摒弃四张等权 KPI 卡片组成的常规后台模板。
- 页面背景继承现有应用工作区，不创建独立的深色页面背景。
- 藏青是唯一品牌主题色；正常信息通过藏青色阶表达，红色和琥珀色仅用于需要注意的异常状态。
- 仅使用现有接口已经返回的数据，不虚构完成率、趋势、目标值或考勤评分。
- 保留现有业务行为，包括摘要加载、权限判断、日历加载和日期明细交互。

## 页面结构

### 1. 月报页首

页首使用克制的横向信息行展示月份、部门、员工编号和姓名，例如：

`2026年5月 / 制造一部 / 100701010 · 余兆中`

主标题为“五月考勤月报”。月份来自当前激活账套；未绑定管理人员时使用现有安全回退文案，不阻断其余内容。

### 2. 月度主视觉

主视觉是一块大幅横向月报版面，而不是多个独立 KPI 卡片。版面使用深藏青底和浅色文字，承担全页最强的视觉重心。

左侧展示超大字号的本月出勤天数，保留“天”作为单位。右侧使用三条纵向排布的数据展示剩余福利、剩余调休和迟到早退。三项数据通过字号、细分隔线和藏青浅色层级区分，不再各自包裹为卡片。

版面下方根据已有摘要字段生成一句确定性的月度描述。文案只陈述接口可以证明的事实，例如有迟到早退分钟数时提示需要关注，没有迟到早退时描述本月记录平稳；不得推断绩效等级或与上月比较。

### 3. 考勤月历

日历位于主视觉下方，是页面的主要明细区域。保持现有 `AttendanceCalendarGrid` 的日期选择和明细弹层行为，但为首页增加限定作用域的编辑式视觉覆盖，避免影响其他复用该组件的页面。

- 弱化单元格边框，形成连续的月度时间版面。
- 星期标题、普通日期和周末使用藏青灰阶建立层级。
- 正常出勤使用浅藏青底或藏青圆点，不使用大面积绿色。
- 迟到、早退、缺勤保留小面积红色或琥珀色标记，确保异常可辨认。
- 请假和出差使用不同藏青深浅表达，同时保留文字标记，不能仅依赖颜色传达含义。
- 手工修正、未计实勤等现有业务标记继续保留。
- 日历顶部的摘要徽章改为一行轻量的“本月注释”，避免与主视觉指标竞争。
- 图例继续完整展示，但使用更轻的排版并移至日历底部。

### 4. 请假构成与数据注脚

请假构成位于日历下方，作为横向数据注脚呈现，不再放入独立的侧栏卡片。各类型使用统一藏青色阶和明确的名称、数值；数值越大可使用越深的色阶，但文本始终提供完整信息。

当所有请假与外勤类型均为零时，显示“本月无请假记录”。数据状态信息缩小为页尾辅助文字，显示现有 `support_message` 或空状态文案。

## 视觉规范

### 色彩

- 页面背景：直接继承工作区的 `--ent-secondary-bg` 及现有点阵背景。
- 主藏青：建议 `#153354`，用于月报主视觉、标题和关键文字。
- 深藏青：建议 `#0B2239`，用于主视觉层次和高对比文字。
- 浅藏青：建议从主藏青混合白色形成三个等级，用于日历和请假构成。
- 普通正文与边框：优先复用现有 `--ent-text`、`--ent-text-secondary`、`--ent-border-strong`。
- 异常色：红色仅用于缺勤或严重异常；琥珀色用于迟到、早退等提醒。

所有首页颜色定义限制在查询首页作用域内，不修改全局 token，不改变其他页面主题。

### 排版

- 沿用系统中文字体栈，避免引入网络字体或新依赖。
- 标题采用大字号、紧行高和较强字重，形成编辑式视觉。
- 数字使用等宽数字特性，主出勤数字成为页面最大字号。
- 小型英文眉题仅作为辅助装饰，中文信息始终是主要阅读内容。
- 内容最大宽度受控并居中，宽屏不无限拉伸；窄屏转为自然的单列阅读顺序。

### 形状与层次

- 主视觉允许较大的圆角和轻微内层光感，但不使用发光霓虹效果。
- 其余区域尽量依靠留白、细线和文字层级组织，减少白色卡片数量。
- 阴影保持轻微，只用于主视觉与可交互日历单元，不制造悬浮面板堆叠感。

### 动效

- 首次加载时，标题、主数字和辅助指标以短距离、低幅度方式依次进入。
- 数字继续使用现有 `KpiNumber` 动画。
- 日期悬停反馈保持轻微，不缩放到影响网格稳定性。
- `prefers-reduced-motion: reduce` 下禁用新增入场与位移动画。

## 响应式行为

- 桌面端：月报主视觉为左右结构；日历占据完整主内容宽度；请假构成为横向注脚。
- 中等宽度：主视觉仍保持两区，但收紧字号和间距；日历允许格内信息适度收缩。
- 移动端：页首信息自动换行；主数字、辅助指标依次纵向排列；日历保持七列并减少格内非关键文字；请假构成改为纵向列表。
- 页面不能产生新的横向滚动；现有侧栏收起与展开不改变首页结构稳定性。

## 数据与组件边界

`QueryHomePage` 继续负责：

- 加载查询首页 bootstrap 数据并确定当前账套月份。
- 加载首页摘要和管理人员信息。
- 使用首页摘要中的 `manager.emp_id` 加载个人考勤日历。
- 处理摘要、日历、权限和空状态。
- 将已有摘要字段转换为月报展示数据和事实型总结文案。

`AttendanceCalendarGrid` 继续负责通用日历行为。首页视觉调整优先通过查询首页容器的限定选择器完成；只有在限定样式无法表达必要结构时，才增加小型、向后兼容的展示属性。不得改变管理端等其他页面中的默认日历表现。

## 加载、错误与权限

- bootstrap 初始化失败：继续显示全页 `ErrorState`。
- 首页摘要加载中或失败：继续使用现有加载和错误组件，失败时不展示不完整的摘要版面。
- 日历加载失败：仅在日历区域显示错误，不影响已经加载的月度摘要。
- 日历接口返回 400 或 403：继续隐藏日历区域，不暴露无权限或超范围信息。
- 没有管理人员 `emp_id`：不请求日历，其他摘要内容正常显示。
- 没有请假或外勤记录：显示明确空状态，不渲染无意义的比例条。

## 文件范围

预计只修改与首页直接相关的文件：

- `frontend/src/pages/query/QueryHomePage.tsx`
- `frontend/src/pages/query/QueryHome.css`
- `frontend/src/pages/query/QueryHomePage.test.tsx`

若首页日历的限定样式确实无法通过现有 DOM 实现，才考虑对 `AttendanceCalendarGrid` 增加向后兼容的样式入口及相应测试。不会改动后端接口、路由或全局应用外壳。

## 验收标准

- 首屏明确表达“本月整体表现”，出勤天数是视觉焦点。
- 页面不再呈现四张等权 KPI 卡片和右侧堆叠面板的旧结构。
- 首页背景与其他工作区页面一致，藏青成为唯一品牌主题色。
- 现有摘要字段、个人身份、考勤日历、请假构成和数据状态均有清晰呈现。
- 首页不重新出现账套选择、数据范围、角色标签或其他已移除内容。
- 日历的日期详情交互、错误隔离和 400/403 隐藏行为保持不变。
- 桌面端与移动端均无新增横向滚动，关键信息层级稳定。
- 现有首页测试更新并通过，新增事实型总结和结构测试，前端完整构建通过。
